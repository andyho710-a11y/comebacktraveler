## Decision

**Critical launch blocker: NO — NON-BLOCKING TECH DEBT for this static Hosting + isolated RFQ Functions architecture.**

Critical GHSA-26w7-cxv4-gfx2 requires processing an attacker-controlled AVIF through Astro/Sharp/libheif. Maintainer source: https://github.com/withastro/astro/security/advisories/GHSA-26w7-cxv4-gfx2 . No CVE assigned in that advisory. Code/config and deployment dependency evidence below show no such public path and neither Astro nor Sharp in Functions production dependency lock. This is an exposure assessment, not a statement that the vulnerable installed version is safe.

Root npm audit counts **13 vulnerable packages**, not 13 unique advisories. npm severity rollup: 2 moderate, 10 high, 1 critical. Each package can contain multiple GHSA entries, and inherited dependency effects are shown separately. Functions npm audit --omit=dev: **0**. No lock/package upgrade performed.

## Deployment and evidence boundaries

- astro.config.mjs has no server output/adapter; Hosting deploys dist only, containing static files, not node_modules or a Node server.
- firebase.json Functions source is functions/ with independent package-lock.json and main lib/functions/src/index.js; root dependencies are not deployed as Functions dependencies.
- functions/tsconfig.json only compiles backend and shared RFQ schema. Imports use Firebase Admin/Functions and node crypto/net; no root package imports.
- RFQ attachments are rejected, no file upload; server parses strict JSON, never image/YAML/TOML/CSS/SVG/deserialization library formats.
- Browser JS application import graph contains only project modules; built HTML has no astro-island framework hydration path. No public runtime image optimizer or build/dev server.
- Evidence: root-audit.json, functions-audit.json, functions-tree.json, reachability.txt, package locks, dist inventory. Fresh npm registry audit returned the recorded advisory IDs/ranges; public maintainer critical advisory was inspected in visible browser.
- Known limitation: local development/build can still encounter hostile repository or dependency input. Keep build input reviewed and dev server loopback. Any SSR, image upload, remote image processing, islands/actions change must reopen this security gate.

## Minimal remediation / security gate policy

Do not upgrade the whole site to hide a number. Schedule a separate reviewed toolchain patch, first compatible updates (RSS, nanoid, source-map-js, Vite), then Astro/Sharp compatibility investigation for AVIF RCE and later decoder issues. Rebuild and re-run complete protected production byte gates, frontend regressions and full typecheck delta. No critical/high affected runtime dependency is permitted in RFQ Functions. If a new Functions audit detects one, or a new public image/parser path becomes reachable, stop backend launch until the narrow fix is verified.
